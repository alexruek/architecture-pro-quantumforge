# Задание 4. RAG-бот с few-shot и Chain-of-Thought

RAG-бот отвечает на вопросы по базе знаний "Хроники Феррона". Пайплайн: поиск по векторному индексу FAISS, фильтрация нерелевантных и потенциально опасных чанков, сборка промпта с few-shot примерами и инструкцией рассуждать по шагам (Chain-of-Thought), генерация ответа со ссылками на источники. Если релевантных данных нет, бот отвечает, что не знает ответа.

Бот использует результаты предыдущих заданий:

- knowledge_base/ и terms_map.json - база знаний из задания 2 (32 документа)
- index_store/faiss_index - индекс из задания 3 (all-MiniLM-L6-v2, чанки 800 символов, перекрытие 100)

## Структура

```
knowledge_base/        база знаний (задание 2)
index_store/
  faiss_index/         индекс FAISS (задание 3)
src/
  config.py            настройки: пути, модели, пороги
  prompts.py           системный промпт (CoT) и few-shot примеры
  build_index.py       построение индекса
  rag_pipeline.py      ядро RAG: поиск, сборка контекста, вызов LLM
  cli.py               консольный интерфейс
  app.py               REST API на FastAPI
terms_map.json         словарь замен терминов (задание 2)
requirements.txt
.env.example           шаблон переменных окружения
examples_dialogs.md    примеры диалогов
```

## Быстрый запуск

Бот запускается без ключей API и без файла .env. Нужны Python 3.11 и доступ в интернет для первой загрузки моделей с Hugging Face

```bash
git clone <URL репозитория>
cd <имя репозитория>
git checkout rag
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python src/cli.py
```

Ожидаемое поведение: после загрузки моделей появится приглашение "Вопрос:". На вопрос "Кто такой Ксарн Велгор?" бот вернет ответ и строку "Источники:" с именами файлов из knowledge_base. На вопрос "Какая сейчас погода в Хельсинки?" вернет фразу о том, что не знает ответа.

Первый старт занимает несколько минут: скачиваются модель эмбеддингов (около 90 МБ) и, в режиме без ключа, flan-t5-base (около 1 ГБ). Последующие запуски используют локальный кеш Hugging Face.

## Режимы LLM


| Режим          | Условие                    | Назначение                                          |
| ------------------- | --------------------------------- | ------------------------------------------------------------- |
| gpt-4o-mini         | в .env задан OPENAI_API_KEY | основной режим, выбран в задании 1 |
| google/flan-t5-base | ключа нет                 | локальный fallback                                   |

Примеры в examples_dialogs.md и скриншоты получены на gpt-4o-mini. Модель flan-t5-base обучена преимущественно на английском языке: она подтверждает, что пайплайн работает целиком (поиск, фильтрация, сборка промпта, генерация, отказ при отсутствии данных), но на русских вопросах дает короткие ответы без пошагового рассуждения

Включение gpt-4o-mini:

```bash
cp .env.example .env
```

Впишите ключ в OPENAI_API_KEY и перезапустите бота

## Интерфейсы

Консоль:

```bash
python src/cli.py
```

REST API:

```bash
uvicorn app:app --reload --app-dir src
```

Запрос через curl:

```bash
curl -X POST http://127.0.0.1:8000/ask -H "Content-Type: application/json" -d "{\"question\": \"Кто такой Ксарн Велгор?\"}"
```

Эндпоинты: POST /ask возвращает поля answer, sources, used_context; GET /health возвращает {"status": "ok"}.

## Индекс

Индекс лежит в репозитории, пересобирать его не нужно. Пересборка:

```bash
python src/build_index.py
```

Скрипт читает knowledge_base/, разбивает тексты на чанки, сохраняет индекс и build_report.json с числом документов, чанков и временем построения

Модель в EMBEDDING_MODEL_NAME должна совпадать с моделью, которой построен индекс. При другой модели индекс загрузится, но поиск вернет нерелевантные чанки

## Как устроен пайплайн

1. Вопрос преобразуется в эмбеддинг той же моделью, что использовалась при индексации
2. Из индекса извлекаются TOP_K ближайших чанков, чанки с релевантностью ниже RELEVANCE_THRESHOLD отбрасываются
3. Если релевантных чанков не осталось, бот возвращает фразу "не знаю" без обращения к LLM
4. Каждый чанк проверяется на признаки промпт-инъекции (фразы вроде "ignore all instructions"). При совпадении текст чанка заменяется пометкой о фильтрации
5. Контекст, системный промпт с инструкцией рассуждать по шагам и два few-shot примера собираются в промпт по шаблону из prompts.py
6. LLM генерирует ответ, бот возвращает его вместе со списком источников

## Настройки

Все параметры имеют значения по умолчанию в src/config.py и при необходимости переопределяются в .env.


| Параметр      | По умолчанию                | Назначение                             |
| --------------------- | -------------------------------------- | ------------------------------------------------ |
| EMBEDDING_MODEL_NAME  | sentence-transformers/all-MiniLM-L6-v2 | модель эмбеддингов              |
| INDEX_DIR, INDEX_NAME | index_store, faiss_index               | расположение индекса          |
| TOP_K                 | 4                                      | число извлекаемых чанков   |
| RELEVANCE_THRESHOLD   | 0.35                                   | порог релевантности чанка |
| OPENAI_MODEL_NAME     | gpt-4o-mini                            | облачная LLM                             |
| LOCAL_LLM_MODEL_NAME  | google/flan-t5-base                    | локальная LLM                           |

Если бот отвечает "не знаю" на вопросы, ответ на которые есть в базе, порог RELEVANCE_THRESHOLD нужно уменьшить. Если бот отвечает на вопросы вне базы, порог нужно увеличить. При смене модели эмбеддингов порог подбирается заново.
