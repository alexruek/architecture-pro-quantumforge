# Задание 3. Векторный индекс базы знаний

## Модель эмбеддингов

- Название: sentence-transformers/all-MiniLM-L6-v2
- Репозиторий: https://huggingface.co/sentence-transformers/all-MiniLM-L6-v2
- Размер эмбеддинга: 384
- Выбрана в задании 1 как локальный вариант без затрат на API и без передачи данных во внешние сервисы.

## База знаний

- Источник: knowledge_base/ (задание 2), вымышленная вселенная "Хроники Вон", 32 документа + terms_map.json.
- Формат файлов: Markdown, один файл - одна сущность (персонаж, планета, технология, событие).

## Параметры разбиения на чанки

- Инструмент: RecursiveCharacterTextSplitter (langchain-text-splitters).
- Размер чанка: 1200 символов (при 800 заголовок самого длинного документа отделялся в отдельный чанк из 35 символов, который попадал в выдачу почти на любой запрос).
- Перекрытие: 100 символов.
- Разделители по приоритету: абзац, строка, предложение, слово.

Для каждого чанка сохраняются метаданные: путь к исходному файлу, заголовок документа, id чанка и его порядковый номер внутри документа. Это нужно, чтобы бот в задании 4 мог ссылаться на источник.

## Векторная база

- FAISS (faiss-cpu), локальное хранилище без внешней инфраструктуры.
- Индекс сохраняется в папку faiss_index/ (файлы index.faiss и index.pkl).

## Как получить метрики индексации

После запуска build_index.py (см. CHECK.md) в корне проекта появляется файл index_report.json со следующими полями:

- embedding_model - использованная модель
- embedding_dim - размерность вектора
- documents_count - количество исходных документов
- chunks_count - количество чанков после разбиения
- chunk_size, chunk_overlap - параметры разбиения
- generation_time_sec - время генерации эмбеддингов в секундах

Эти цифры зависят от железа, на котором запускается скрипт, поэтому вписывать их в README вручную не нужно - файл создается автоматически при каждом запуске.

## Пример запроса к индексу

Файл src/query_index.py прогоняет три тестовых запроса и выводит топ-3 ближайших чанка с оценкой расстояния:

- "Кто такой Ксарн Велгор?"
- "Что произошло во время битвы за Саирон?"
- "Как устроен рифт-двигатель?"

Ожидаемый результат: для каждого запроса среди top-3 чанков должен быть чанк из документа, напрямую относящегося к вопросу (например, characters_ксарн_велгор.md для первого запроса).

## Структура файлов

```
knowledge_base/        - база знаний из задания 2
src/build_index.py     - построение индекса
src/query_index.py     - тестовые запросы к индексу
requirements.txt       - зависимости
faiss_index/            - появится после запуска build_index.py
index_report.json       - появится после запуска build_index.py
```
