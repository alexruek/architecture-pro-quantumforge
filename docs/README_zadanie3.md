# Задание 3. Векторный индекс базы знаний

## Модель эмбеддингов

- Название: intfloat/multilingual-e5-small
- Репозиторий: https://huggingface.co/intfloat/multilingual-e5-small
- Размер эмбеддинга: 384
- Максимальная длина входа: 512 токенов, размер модели около 470 МБ, работает на CPU.

В задании 1 выбраны локальные эмбеддинги Sentence-Transformers: без затрат на API и без передачи документов во внешние сервисы. Конкретная модель взята многоязычная, потому что база знаний и вопросы на русском языке. Первая версия индекса строилась на англоязычной all-MiniLM-L6-v2: на русских вопросах она давала низкие и почти одинаковые оценки для всех документов, нужный документ часто не проходил порог релевантности.

Модели семейства E5 обучены на парах "вопрос - фрагмент" и ждут служебные префиксы: "query: " перед запросом и "passage: " перед документом. Префиксы добавляет обертка E5Embeddings в src/embeddings_factory.py, векторы нормализуются. Все скрипты получают эмбеддинги через одну функцию get_embeddings, поэтому индекс и запросы кодируются одинаково.

## База знаний

- Источник: knowledge_base/ (задание 2), вымышленная вселенная "Хроники Феррона".
- Формат файлов: Markdown, один файл - одна сущность (персонаж, планета, технология, организация, событие).

## Параметры разбиения на чанки

- Инструмент: RecursiveCharacterTextSplitter (langchain-text-splitters).
- Размер чанка: 1200 символов, перекрытие: 100 символов.
- Разделители по приоритету: абзац, строка, предложение, слово.

Документы базы короткие (до 900 символов), поэтому при размере 1200 каждый документ - один чанк. При размере 800 заголовок самого длинного документа отделялся в отдельный чанк из 35 символов, который попадал в выдачу почти на любой запрос. Для длинных документов чанкинг работает как обычно: чанк в 1200 символов русского текста укладывается в лимит модели 512 токенов.

Для каждого чанка сохраняются метаданные: source (путь к файлу от корня проекта), title, chunk_id (имя файла и номер, например 08_horrak_000) и chunk_index. По ним бот показывает источники ответа.

## Векторная база

- FAISS (faiss-cpu, IndexFlatL2), локальное хранилище без отдельного сервиса.
- Индекс сохраняется в faiss_index/: index.faiss и index.pkl, рядом manifest.json со списком файлов и их хешами (задание 6).

## Код

| Файл | Назначение |
| --- | --- |
| src/build_index.py | первая сборка индекса: чтение, чанкинг, эмбеддинги, сохранение индекса и отчета index_report.json |
| src/query_index.py | три тестовых запроса к индексу без LLM |
| src/embeddings_factory.py | выбор модели эмбеддингов, префиксы E5, офлайн-заглушка для автотестов |
| src/update_index.py | точечное обновление индекса (задание 6) |

Модель, пути и параметры чанков заданы в src/config.py.

## Метрики индексации

Файл index_report.json создается при каждом запуске build_index.py:

- embedding_model, embedding_dim - модель и размерность вектора;
- documents_count, chunks_count - число документов и чанков;
- chunk_size, chunk_overlap - параметры разбиения;
- generation_time_sec - время генерации эмбеддингов в секундах.

## Пример запроса к индексу

src/query_index.py задает три запроса и печатает по три ближайших чанка с оценкой релевантности (чем больше, тем ближе):

- "Кто такой Хоррак?"
- "Что такое Странник Тысячелетия?"
- "Что произошло во время Битвы при Йовене?"

Вывод последнего запуска сохранен в docs/query_example.txt. Ожидаемый результат: первым идет чанк из документа о сущности из вопроса (08_horrak, 20_strannik_tysyacheletiya, 30_bitva_pri_yovene).

## Запуск

```bash
python src/build_index.py
python src/query_index.py | tee docs/query_example.txt
```
